# dsh-daoing-memory 能力点与特色点

这份文档描述本插件的能力全貌：顶层设计特色、agent 工具面使用流程、以及记忆的数据结构。若你关注"为什么这么设计"，可另见 [DESIGN.zh-CN.md](./DESIGN.zh-CN.md)。

## 一、顶层设计特色（每条如何实现）

### 1. 「生 · 用 · 修 · 记」四字闭环
这套系统不把记忆当成一个"仓库"，而当成一条**有生命周期的知识治理流程**。任何一条知识都要完整经历"诞生 → 被使用 → 被修正 → 被记录"四个阶段，每个阶段有独立的手段与入口。这样保证：一条记忆不是"写进去就完了"，而是围绕真实使用不断被验证、被修正、被淘汰，最终只留下经得起检验的知识。工具与阶段一一对应，agent 在正确时机调用正确阶段的工具，就自然走完这个闭环。

### 2. 记忆必须靠挣，无钦定
一条经验诞生时不是"已可信"，而是**候选/待印证**。它能否晋升为"活跃/可信"、能否进入召回视野，取决于**是否被真实使用并回报成功**：成功一次计一次正向样本，失败计负向样本，信任度由这些样本经贝叶斯规则计算，用得越久越可信。**没有任何来源（哪怕撰写者本人）能绕过验证就给一条经验盖上"高可信"章**。于是"凡被信用的，必是被验证过的"，从机制上杜绝凭空捏造的记忆被当作行事依据。

### 3. 两种记忆刻意分离
系统把记忆分成性质完全不同的两类。
- 一类是**关于"这个用户"的稳定认知**——他是谁、习惯怎么协作、在意什么还没了结的心事。它解决的是"了解这个人"，来源只有用户本人的言行。
- 另一类是**关于"某一类情形下怎么做才对"的知识**——比如某个操作路径可行、某条路是死路。它描述的是"情境 → 正确做法"，所以能在相似情形下被复用到别处，解决的是"把事情做对"，来源可以是任何一次成功或失败的经历。

二者在来源、写入方式、召回时机、治理手段上都分开：前者只从用户本人提炼，后者能从经历沉淀。分开是为了不让项目细节/任务上下文混进对用户的稳定认知，也不让个人特质被误当成通用做法。

### 4. 人始终在回路中
系统默认不信任任何"自动写定"的知识能自行演变，关键控制权保留给人。两条机制：① 提供浏览器工作台，人能随时查看、纠正、晋升、删除、归档任何记忆；② **只有"人明确批准过"的经验才允许自我成长**（不断吸收新证据而变强），机器自己提炼的经验没有自我修改的权限。二者合起来，保证记忆是"人机共享、人始终把关"的资产，而不是机器自说自话、失控膨胀的黑盒。

### 5. 只增不删的审计账本
一切改变记忆的操作都不直接改旧记录，而是"**向账本追加一条新记录**"，且每条记录都**带上一条记录的指纹**，首尾相连成一条不可篡改的链。于是任何一次"从哪来、改了什么、谁改的、为何改"都能完整回查；要回滚，就沿链把状态恢复到某旧节点。因为旧记录从不删除，记忆被污染或漂移时能定位、能归因、能恢复，而不是无声坏掉。

### 6. 作用域防污染
每条经验都声明自己属于哪个领域/上下文；召回时只取"同一领域"或"**显式声明跨域共享**"的经验。这样，"Windows 构建"的教训不会被用在别的领域。跨域共享是**默认关闭的特权**，避免一条局部经验意外污染所有场景。

### 7. 经济注入预算
系统为"每次能往上下文里注入多少条记忆"设了预算（按估算的 token 计量），并按每条经验的价值（可信度 × 相关度）排序，只把最值得的注入，其余省略。同时召回必须明确告诉 agent"有没有相关经验"——**没有就明确说没有**，这本身就有价值（让 agent 知道这是全新探索，别硬套）。预算与"负向通道"合起来，避免"记忆一股脑塞满上下文"和"没记忆却硬编"两个极端。

### 8. 防投毒边界
系统对"记忆能来自谁"做了硬性区分：能塑造"对用户的稳定认知"的，**只有用户本人说出口的话**；外部内容（书/文档/他人言论/助手建议）再精彩也只能沉淀为"通用做法（经验）"，绝不允许被当成"关于用户的事实"。对拿不准的内容，系统不硬猜，而是**挂起交人工裁决**。这样即使上下文中混入被引导、被注入的噪声，也不会污染对用户的认知，更不会据此做出对用户不利的推断。

### 9. 元经验：把人删记忆的判断，反哺成系统未来行为的准则
当人觉得某条记忆不行、把它删除时，删除会被**标记原因**。系统把这些删除原因累积起来，在积累到一定程度后做一次总结，形成一条"元经验"。这条元经验反过来指导以后提取记忆时**别再产出会被删掉的同类东西**。它由系统生成、跨域共享，且受保护（不能删除、只能归档），因为它是整个系统自我纠偏的依据——**把"人认为哪些记忆不该有"的判断，反哺成系统未来的行为准则**。

## 二、agent 工具面（每个工具如何使用、使用流程）

### 总流程（一个任务的记忆闭环）
1. 任务前 → ① `memory_recall`（用）
2. 任务中 → 若召回给了未验证的"候选试探"，可选一条真试一次
3. 任务后 → ② `memory_refine`（生）沉淀为候选
4. 用过之后 → ③ `memory_report`（用·验）——**使用即验证**
5. 经验被挑战/失败 → ④ `memory_revise` + ⑤ `memory_verify`（修）
6. 重要交互 → ⑥ `memory_fact` →（节律到）⑦ `memory_extract`（记）
7. 读了外部来源 → ⑧ `memory_ingest`（摄取）
8. 经验堆积 → ⑪ `memory_consolidate`（巩固）
9. 查历史 → ⑩ `memory_ledger`（账本）

### 判重规则：先机械粗筛，再 LLM 语义终判
- **为什么需要两级**：经验库里同一类教训可能被反复沉淀——不同会话、不同表述、不同路径，指向的其实是同一个可复用教训。只靠词面去重会漏掉"表述不同但含义相同"的重复；完全交给模型判，成本高且可能误并。所以拆成两步：**机械层快速筛，语义层精准判**。
- **触发时机**：`refine` / `ingest` 提交一条新经验时，系统先在库里按**近似度 / 词面重叠**快速筛出一批可疑的"近乎重复"候选（这一步轻量、便宜、覆盖全量）。
- **终判（交给模型）**：把"新经验 + 这批候选"一起交给当前会话选定的模型做语义判断，给出三种结论之一：
  - **`different`**（是不同的教训）→ 照常沉淀为新候选，**且跳过机械门控**——不因外观相似被拦，确保"不同情境下的细微差异"不被误杀。
  - **`merge`**（应并入已有经验）→ 仅当目标经验是"**人批准 + 活跃**"时，才触发它的**自我成长**，把这次的新表述 / 新证据吸收进去、经验变强；否则退化为佐证。
  - **`duplicate`**（纯重复、无信息增益）→ **拒收**新提交，但给已有经验**增加一次佐证计数**（corroborate），让这次提交白得一次验证。
- **模型路由**：判重所用模型取自当前会话的请求头配置（与主对话同源）；若取不到该配置，则**保守返回 `different`**——宁可多存一条候选，也不冒险把两条不同的经验错误合并。
- **批内也判重**：一次 `ingest` 提交的多条新经验之间，也会用词面重叠去重，避免同批内自相重复。
- **与工具返回对应**：`memory_refine` / `memory_ingest` 返回的 `corroboratedId`，就是"被判为 merge / duplicate 后，指向的那条被并入 / 被佐证的经验 id"；`accepted=false` + 该 id，说明这次提交没新增，而是帮已有经验积累了一次佐证。
- **目的**：既避免"同一条教训被反复入库堆积"，又避免"语义相近但确有差异的有效经验被误并"。判重看的是"是否指向同一个可复用教训"，而不是字面是否相同。

### ① memory_recall（用·任务前）
- 目的：开始复杂任务前，召回与当前情境相关的经验，避免重蹈覆辙、直接复用可行路径。
- 时机：**复杂任务开始前**（有判断成本、可能走弯路/撞墙/有已知死路风险的任务）；平凡调用不必。
- 关键参数：`situation`（新任务情境，写任务类型/领域/症状/约束）；`context`（可选，领域作用域，只有同域或跨域共享才被召回）；`topK`（裁决前候选上限）；`deep`（正常集合太薄时是否翻归档经验）。
- 返回要读懂：`items`（每条带**相关度分数 + 裁决：直接采用/作为参考/仅为线索** + "可能与当前情境冲突的边界"警告）；`none=true`（**没有相关经验，这是正常**——全新探索，别硬套）；`candidateTrials`（未经验证的候选，可选一条真试一次，试后必须报告）；`omitted/estimatedTokens`（预算内省略与估算）；`consolidationDue`（提示该合并了）。
- 流程：调用 → 按裁决行动（direct 直接照做；reference 参考改造；clue 仅当线索）→ 尊重冲突警告、别踩边界 → `none` 则放心探索 → 若试了候选，成功后 `memory_report` 转正。

### ② memory_refine（生·任务后）
- 目的：把一个走过多步判断的复杂任务，提炼成一条经验候选。
- 时机：任务后，且过程有"值得复用的判断"——走过弯路、纠正过方向、撞到边界、或确认死路。平凡单工具调用不要提炼。
- 关键参数：`kind`（positive=可行路 / negative=确认死路，negative 需 `failureReason`）；`family`（任务族标签）；`gist`（**一句**可复用教训，需分号塞多条就拆成多次）；`situation`（触发召回的**情境类别**，泛化，不是"本次任务"）；`path`（顺序动作步骤）；`reasoning`（可迁移的判断背景——"什么情境下这条路成立、因为什么、边界在哪"，**不能写"本会话/本次/用户当场…"**）；`limits`（适用边界）；`evidence`（证据指针，trace/session/note 至少一个非空，无证据被拒）；`complexity`（复杂度门控：轨迹 token 数/步数/是否失败，低于门槛且无失败会被拒；`humanMarked` 可绕门控）；`context`（作用域）。
- 原则：一条=一个教训；写通用教训供未来复用；一条=一次调用。返回 `accepted=false` 时看 `reason`；`corroboratedId` 表示"这条和已有某条重复，已作佐证"。

### ③ memory_report（用·验·使用后）
- 目的：报告"使用某条经验"的结果——**使用即验证**。
- 时机：按召回经验行动之后。
- 关键参数：`id`（+可选 `revision`，省略为当前活跃版，传 draft 修订版用于检验）；`outcome`（success/fail；对负经验，success=预测命中、死路确实死，也算正结果）；`attribution`（fail 时：experience=经验本身缺陷 / environment=环境网络权限，**绝不扣经验分** / unrelated=无关 / unknown=信号不足不计）；`evidence`（客观证据文本，**可覆盖主观归因**）；`dedupeKey`（幂等键，同一执行只报一次）；`tokensUsed/Saved`。
- 流程/效果：success 于 candidate → **转正 live**；success 于 draft 修订版 → **adopted**（旧版转 superseded 可回滚）；fail 且归因 experience → **challenged**（隔离出召回，需修订）；候选试探失败 → **进冷宫**。
- 注意：环境失败不扣经验分；**证据优于声明**。

### ④ memory_revise（修·提出修订草案）
- 目的：对一条**被挑战（challenged）**的经验提出修订草案（版本 +1）。
- 时机：一条经验因失败被隔离后，你诊断出根因。
- 关键参数：`id`（必须 challenged）、`reason`（诊断：失败根因 + 本次改了什么）、可替换的 gist/situation/path/reasoning/limits。
- 之后：草案仍是候选，需 `memory_report`（针对该修订版 revision）成功一次，或 `memory_verify` 影子重放通过，才转正；旧版转 superseded 可回滚。

### ⑤ memory_verify（修·影子重放）
- 目的：真实重试昂贵/危险时，用"已知结果的历史样本"重放草案，通过就直接转正。
- 时机：有修订草案，且真实验证代价大。
- 关键参数：`id`、`revision`（要验证的草案版本）、`samples`（数组：历史情境 + 已知结果 success/fail）。
- 返回：`passed` + `agreement`（一致率）。

### ⑥ memory_fact（记·日记）
- 目的：追加一条与用户的重要交互记录（事件层，**永久、永不自删**）。
- 时机：重要交互后及时。
- 关键参数：`kind`（said/delegated/promised/happened/preference/other）、`content`（一段讲清 who/what/when）、`sessionRef`（溯源）、`tags`（可选）。
- 返回：`extractionDue` 为真→**提炼周期到了，应调 `memory_extract`**；`pending` 给待提炼日记。
- 意义：日记是提炼的原材料；也保证对话可双向追溯。

### ⑦ memory_extract（记·上升通道）
- 目的：把待提炼日记蒸馏成两类——①**画像事实**（AI 对用户的稳定认知）②**关心事项**（替用户记着的未了心事/备忘）。
- **时机（何时该提取）**：记忆是**节律触发**，不是每记一条就提一条。**触发条件（两个必须同时满足）**：① 累积的**未提取日记达到阈值**（默认 8 条）；② **距上次提取已过最小间隔**（默认 12 小时）。到点时，下一次 `memory_fact` 会明确返回"提取周期已到"，并给出**待提取的日记窗口**。触发方式分**自动节律**与**手动**两种。**提取时会先纳入"删除反馈"元经验**：若近期有较多经验被人删除，系统会先把删除原因汇总成一条元经验随本次提取返回，避免这次提出的又被删掉。提取完成会留档（触发方式/摘要/产出画像/消耗日记数）。
- 关键参数：`proposals[]`（画像提案：category=identity/preference/communication/habit/thinking/value/delegation/background/other + factKey + value + sourceDiaryIds[]，**只来自用户本人之言**，相同画像保持一条、拿不准挂 other 人工）；`concerns[]`（关心事项：action=new 必带 background / mention / status=ongoing/concluded/recurring/paused；**反复习惯→画像；可复用做法→经验；都不是关心事项；不是给会话打主题标签**）；`summary`（本次提炼窗口一句话）。
- 原则：**项目内容/目标/决定/环境配置都不是画像**——未闭环的进 concern，其余丢弃。

### ⑧ memory_ingest（摄取·外部来源）
- 目的：从任意外部来源（书/skill/文档/文章/别人言论）批量提取经验候选。
- 时机：读完/提取完一个想让经验库学会的外部来源。
- 关键参数：`sourceType`（conversation/document/skill/book/note/other，决定置信先验）、`sourceRef`（溯源）、`context`（作用域）、`note`；`experiences[]`（每条一条教训：kind/family/gist/situation/path/reasoning/limits，negative 加 failureReason）。
- 原则：**绝不**从外部生成画像事实或关心事项；一条=一条可复用教训、多条拆多条；写通用教训（sourceRef 是证据指针）。返回：`accepted`（通过判重与门的候选）、`rejected`（原因）。

### ⑨ memory_human_inject（特殊通道·人工注入）
- 目的：把**人（作者/专家）已确认的通用经验**直接注入经验库，立即以"活跃/可信"状态参与召回；适用于页面上不便操作，或需要快速把确定的知识入厂。
- 时机：人提供的、确定可靠的通用教训。
- 关键参数：kind/family/gist/situation/path/reasoning/limits（negative 加 failureReason）/context/reason（注入原因，用于审计）。**一次一条**；写成可迁移的通用教训。
- 特性：写入即 `source=human / status=live / 信任地板`，并 append 到审计账本（actor=human），账本可校验。
- 注意：默认产生**局部作用域**经验；若需跨域共享，需人工在库上补设跨域标记，并复核账本完整性。

### ⑩ memory_ledger（账本·查询）
- 目的：查询审计账本，看哪些操作发生在哪条记忆上、谁、何时、为何。
- 关键参数：按 objectType（experience/fact/diary/library/concern）、objectId、op 过滤，limit / seqFrom / seqTo 分页。
- 用途：查一条记忆的完整历史、排查漂移、做回滚决策。

### ⑪ memory_consolidate（巩固·合并）
- 目的：把多组关系紧密、重复表达同一条底层教训的经验，合并成一条更精炼的经验。
- 时机：`memory_recall` 给了 `consolidationDue`，或你发现多条经验在重复同一条教训。
- 关键参数：`merges[]`，每个合并组给 family/kind/gist/situation/path/reasoning/limits/sourceIds(≥2)/note；`note` 概括本次运行。
- 原则：**蒸馏共同点、丢弃会话特例**，不是简单拼接；来源被归档（离开召回但可恢复）；合并产物**继承原信任**；**永不硬删除**。

## 三、记忆的结构（表结构 / 前端展示 / 数据关联）

### 数据结构总览（11 张表）
| 表 | 记录的是什么 |
|---|---|
| `memory_meta` | 键值元信息（如 schema 版本号），用于迁移与版本控制 |
| `experiences` | 经验的**家族 + 版本**：一句可复用教训(gist)、适用情形(situation)、动作路径(path)、可迁移的道理(reasoning)、边界(limits)、状态、信任计数、作用域、跨域标记、批准人，以及**提取依据(evidence)、来源(source)、父版本(parent_revision)** |
| `use_reports` | 每次**使用回报**：对哪条经验的哪一版、成功/失败、归因（经验/环境/无关/未知）、是否计入、证据、幂等键 |
| `ledger` | **只增不删的审计账本**：谁、何时、对哪个对象、做了什么、为何做、以及哈希链 |
| `diary` | 与用户的重要**交互日记**（事件层，永不自删），记录 kind/content/session/是否已提取 |
| `facts` | **画像事实**：关于用户本人的稳定认知（分类、键、值、来源日记、佐证次数、有效窗口、被谁替代、锁定/冲突挂起） |
| `extractions` | 每次**提取运行**：触发方式、摘要、产出了哪些画像、消耗了多少日记 |
| `recall_events` | 每次**召回的遥测**：当时的情境、注入了哪些经验、是否为空、作用域 |
| `concerns` | **关心事项**（替用户记着的未了心事）：标题、背景、类型、状态、来源日记、作用域、树形父子 |
| `consolidations` | 每次**合并日志**：把哪些经验合并成了哪一条、备注 |
| `skill_artifacts` | **经验→技能**的产物：来源经验、形态(script/knowledge/checklist/prompt)、草稿/已发布路径、版本、被用/被优化次数、最近反馈 |

### 数据之间的关联
- **经验版本是一条链**：`experiences` 以"家族 + 版本"为主键，`parent_revision` 指向前一版本，形成版本线；"活跃版"= 该家族最新且未删除的版本。修订、合并、被挑战都在这条链上表现出来。
- **使用回报回填到经验**：`use_reports` 的"经验 id + 版本"指向某个具体版本；这些回报被聚合为经验的**信任计数与成败比**，正是经验"靠挣"晋升的依据。
- **账本关联万物**：`ledger` 用"对象类型 + 对象 id"指向任意一张表（经验/日记/画像/技能…），并靠哈希链（每条带上一条的指纹）保证不可篡改；因此任何一条记录都能回查"从哪来、改了什么、谁改的、为何改"。
- **提取依据与可追溯**：每条经验自带 `evidence` 证据指针（trace/session/note，无则拒收），并叠加 `source`（谁造的）、`parent_revision`（版本链回看前身）、`ledger`（全程审计 + 哈希链）共四层做到可追溯；而画像(`facts`)与关心事项(`concerns`)另用 `sourceDiaryIds` 锚回其来源日记。
- **日记是上游原材料**：`facts` 与 `concerns` 都通过"来源日记 id 数组"引用 `diary`（多对多），说明一条画像/关心事项是"从哪些日记提炼来的"，可反向追溯。
- **画像自身有生命周期**：`facts` 用"有效起始/结束时间"定义它何时成立、何时失效；`superseded_by` 指向替代它的新画像，形成**画像替代链**；`conflict_pending` 表示存在冲突、等待人工裁决；`locked` 表示被锁定。
- **关心事项是一棵树**：`concerns.parent_id` 自引用形成父子结构，一条大事项可挂若干子项；状态（进行中/已了结/反复出现/暂停）随用户实际进展更新。
- **合并是"汇总而非删除"**：`consolidations.merged_ids`（被合并的经验 id 们）→ `produced_id`（产出的那条新经验），来源经验进入归档但**永不物理删除**。
- **技能产物挂在来源经验上**：`skill_artifacts.parent_experience_id` 指向那条被转化成的经验的家族，一条经验可对应一个技能面板。
- **召回有遥测**：`recall_events` 记录"这次召回了谁、注入了谁、是否为空"，便于事后下钻某次召回为何没有/注入了哪些经验。

### 前端如何展示
前端（记忆管理卡片/工作台）本质是把上面这些表渲染成可读、可操作的面板：
- **经验库面板**：按家族分组、展示版本线；每条用状态色区分（候选/活跃/被挑战/被替代/归档/冷宫）；显示信任度小数、成败计数、作用域、跨域标记、批准人；展开可见 gist / situation / path / reasoning / limits / 证据 / 失败或被挑战原因。
- **使用统计**：从 `use_reports` 聚合，展示一条经验被**成功/失败使用了几次、失败因什么**（环境/无关/经验本身/未知），让人一眼看出"这条是靠得住的，还是该修订的"。
- **审计时间线**：按某个对象过滤 `ledger`，展示谁、何时、做了什么、为何做，用于排查漂移与回滚决策。
- **画像快照**：`facts` 按分类分组，显示来源日记、佐证次数、有效区间、冲突挂起、替代链；关键的是，它能把"画像快照"这一份对用户的稳定认知**注入给 agent**，让 agent 更懂用户。
- **日记流**：`diary` 列表 + 是否已提取标记 + **提取周期倒计时**（还差几条、距上次多久），直接对应"提取时机"。
- **关心事项**：`concerns` 渲染成树 + 状态标签（进行中/已了结/反复/暂停）+ 来源日记，形成"替用户记着的待办/心事"。
- **技能面板**：`skill_artifacts` 展示草稿/待审/已发布状态、被用与优化次数、最近反馈，对应"经验→技能"的转换。
- **提取记录**：`extractions` 列表展示每次触发方式、摘要、产出画像数、消耗日记数，回应"提取时机"与"节律"。
